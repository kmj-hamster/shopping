# 槽位卡牌玩法：三日 Demo 设计规格

> 状态：开发中；阶段A领域模型已实现
> 文档版本：0.2
> 实验分支：`codex/slot-task-prototype`
> 旧玩法归档：`polyomino-demo-v1`
> Demo 内容范围：3个夜晚、12种商店商品、6个每日愿望、2个合成配方、1条完整店主好感线

## 1. 设计目标

这版 Demo 验证的核心不再是空间拼图，而是以下循环：

1. 白天获得稳定收入。
2. 夜晚查看两个私人愿望。
3. 在当晚营业的商店中挑选商品。
4. 结账后，商品成为底部手牌栏中的实体卡牌。
5. 将卡牌拖入愿望、配方或店主请求的槽位。
6. 确认两个每日愿望，或执行会当场完成的合成与店主请求。
7. 点击进入下一天，在黑屏过场中消耗每日愿望物品并显示对应短文案。

体验重点：

- 选择物品是在选择“今晚如何照顾自己”，同时也是隐性的性格测试。
- 商品拥有具体用途，也携带碎片化叙事。
- 规则应当像桌面卡牌一样能被快速看懂：卡牌、槽位、属性图标、短反馈。
- 玩家不会因为随机愿望、商店排班、库存或金钱而进入死档。
- UI 借鉴《密教模拟器》《司辰之书》的卡牌与槽位语法，但不复制其文本、美术、图标或专有设定。

本阶段不制作：

- 白天新闻小游戏，只保留固定工资。
- 20天的完整内容。
- 酒精灯小姐、灯泡男和正式结局判定。
- 五位店主的完整剧情；只完成气球先生一条小型验证线。
- 重复使用衰减，仅保存使用次数供以后启用。

## 2. 为什么从当前版本改造

仓库没有可直接使用的“早期玩法分支”，只有同一条 `main` 历史。回退到早期提交会同时失去后来已经验证过的基础设施，因此新玩法从当前归档版本继续。

### 2.1 保留并改造

- 主地图、进入商店和返回地图的路由。
- 五家零售店与回收站的空间结构。
- 商店营业排班的基本框架。
- 钱包和交易的原子性思想。
- 回收站按比例回收物品的流程。
- 中英双语、`TranslationServer` 和本地化测试。
- 夜晚梦核商场的色彩和 UI 基础样式。
- GUT、Godot MCP、跨平台检查与导出流程。

### 2.2 整体替换

- Polyomino 形状、格阵、旋转、占格和投影。
- 空袋子以及“物品必须先放进格阵才能购买”的规则。
- `PuzzlePieceState`、`PuzzleRules`、`PuzzleBoard` 的运行时职责。
- 旧的每日格阵、泰迪熊/金鱼/磁带格阵和特殊大块。
- 多个任务 popup 与主角黑色卡片大厅。
- 商品拖拽购买；新版本中未购买商品不能被拖动。

### 2.3 最终删除

新系统通过相应测试后，删除所有不再被引用的 Polyomino 脚本、场景、开发用 `PuzzleLab` 和旧测试。不会保留两套运行时系统。

## 3. 核心术语

### 3.1 物品属性

每个物品拥有一个属性字典，属性值范围为1至8。数值0等同于不存在该属性。

属性分为两类，但在数据层使用同一种键值结构：

- 直觉属性：食物、植物、玩具、音乐、柔软、放松、助眠、甜、酥脆、温暖、提神、追忆、幻想等。
- 性相属性：灯、镜、烛、枕。

四种性相：

| ID | 名称 | 意象 |
| --- | --- | --- |
| `lamp` | 灯 | 交流电、夜晚的街角、飞蛾、清醒的夜游者 |
| `mirror` | 镜 | 静室、白衣、追忆、铭记、自省的忧伤 |
| `candle` | 烛 | 幻觉、随想、远古鱼游过卧室的墙 |
| `pillow` | 枕 | 鹅绒被、薰衣草、天明前的慰藉 |

旧版的“花”和“雾”属性不进入新存档；它们分别由“枕”和“烛”替代。

### 3.2 物品实例

同一种商品可以买多份。每一份都是独立的卡牌实例，至少保存：

- 唯一实例 ID。
- 物品定义 ID。
- 获得日期与来源。
- 所在位置：手牌、任务槽、店主请求槽或回收栏。
- 当前任务与槽位 ID。
- 使用次数，Demo 中不产生衰减。

商店货架上的商品贴图不是物品实例。只有结账成功后才生成实例并进入手牌栏。

### 3.3 商店货位实例

商店不保存“某商品库存3”这种堆叠数量，而是保存独立货位：

- 每家零售店初始有6个货位，后续解锁可以增加容量。
- 每个货位最多放一个可购买单位，并拥有稳定的 `shelf_slot_id`。
- 两个相同商品占据两个独立货位；购买其中一个不会影响另一个。
- 货位被购买后变为空位，当晚不会立刻补货。
- 新一天只填补空位到当前容量，不替换没有卖出的商品。
- 补货从店铺商品权重池逐个货位独立抽取，因此允许出现重复商品。
- 货位内容、空位和店铺容量都写入存档。

## 4. 槽位判定语法

每个槽位只能放一张卡。同一张卡不能同时满足两个槽位。

槽位包含四组规则：

1. **必要 `required_all`**：列出的每一种属性都必须存在，才允许放入。
2. **可以 `allowed_any`**：只要存在其中任意一种就允许放入；该组为空时不检查。
3. **不可以 `forbidden_any`**：只要存在其中任意一种就拒绝放入；该组为空时不检查。
4. **数值要求 `value_checks`**：不影响“能否先放入”，只影响每日愿望能否确认、配方或请求能否执行。

放入判定顺序：

1. 满足全部“必要”。
2. 若“可以”非空，至少满足其中一种。
3. 不包含任何“不可以”。
4. 通过后允许放入，即使暂时不满足数值。

数值要求支持三种模式：

- `single`：指定属性必须达到数值，例如 `food >= 2`。
- `any`：一组属性中至少一个达到数值，例如 `max(lamp, pillow) >= 2`。
- `sum`：一组属性数值总和达到数值，主要为后续高级配方预留。

一个槽位的多条数值要求必须全部成立，才能确认或执行对应活动。

示例：“床头留一点东西”可以定义为：

```text
必要：plant
可以：lamp / candle / pillow
不可以：无
确认：max(lamp, candle, pillow) >= 3
```

### 4.1 高亮反馈

玩家点击槽位后：

- 明亮描边：类型与数值均满足，可以完成该槽位。
- 较暗描边：类型满足，可以放入，但数值不足。
- 压暗：违反必要、可以或不可以规则，不能放入。
- 在商店中，货架贴图也使用相同高亮，但仍然不能拖动；玩家必须先购买。

数值不足时操作按钮禁用，并显示一条短反馈，例如“柔软还差1”。不使用长篇规则说明。

## 5. 界面和基础交互

### 5.1 底部手牌栏

- 在地图、普通商店、回收站和任务界面中始终存在。
- 全局共享、容量无限、横向滚动。
- 只显示已结账的物品。
- 卡牌被放入任务槽后暂时从手牌栏消失。
- 从槽位拖出或点击“取回”后，卡牌自动回到手牌栏。
- 卡牌排序默认按“新获得在右侧”，以后可增加商店/属性排序。

### 5.2 商店货架

- 货架固定显示当前店铺的6个独立货位；扩容后可以增加第7个及更多货位。
- 每个有货的货位显示一张商品贴图、名称和价格，不显示 `×2`、`×3` 等堆叠数量。
- 相同商品可以同时占据多个位置，例如“薯条、薯条、可乐”。
- 商品在结账前不是可拖卡牌。
- 点击某个货位打开紧凑详情，并可将这个具体货位选入或移出购物篮。
- 购物篮记录 `shelf_slot_id`，不记录抽象商品数量，也不生成待付款物品实例。
- 点击结账后进行一次原子校验：营业、货位仍有货、金钱全部通过才扣款。
- 结账成功后生成卡牌实例并依次进入底部手牌栏。
- 被购买的货位变空，直到下一天补货。
- 离店时若购物篮非空，仍使用“直接离开 / 结账并离开”的确认流程。

### 5.3 主角任务窗口

- 点击右下角主角头像，打开或关闭唯一的任务窗口。
- 窗口可以拖动，但只存在一个，不再生成多个格阵 popup。
- 窗口顶部设三个分页：`今日清单`、`合成配方`、`请求`。
- `今日清单` 内有当晚两个愿望的小分页。
- `合成配方` 内列出已知配方，选中后切换背景图、槽位和预览。
- `请求` 只显示已经被店主明确提出的请求。
- 切换页面不会取回已经放入的卡牌；它们留在原槽位中，直到结算或玩家主动取回。
- 地图中打开窗口时居中；商店中打开时靠右，露出左侧货架。

### 5.4 每日愿望的确认

- 卡牌满足类型和数值后，玩家点击“确认”。
- 确认只锁定当前选择，不销毁物品、不增加主角性相，也不显示结果文案。
- 已确认的卡牌继续占据槽位，不能被其他任务、配方、送礼或回收使用。
- 在进入下一天之前，玩家随时可以点击“取消确认”。
- 取消后槽位重新可编辑；玩家可以取回卡牌或换成另一张，再次确认。
- 两个每日愿望都处于已确认状态后，下一天按钮才允许开始结算。
- 未付款物品不存在于任务系统，因此不存在“未结账却确认”的状态。

### 5.5 下一天与黑屏结算

玩家点击下一天后，系统按以下顺序执行一次原子结算：

1. 再次验证两个愿望仍已确认，卡牌实例和槽位关系仍有效。
2. 为每个愿望冻结“愿望 ID、物品 ID、结果文案键、贡献性相”的结算快照。
3. 保存尚未执行消耗的 `pending_transition`，然后开始淡出。
4. 画面完全变黑后，准确执行一次卡牌消耗和主角性相增加，把 `consumption_applied=true` 写回存档。
5. 在黑屏中依次显示两个由所选物品决定的短文案。
6. 文案播放结束后增加新一天工资、补充商店空货位、生成新的每日愿望并自动保存。

黑屏过场是每日选择的叙事反馈。确认时不提前泄露完整结果文案，只可通过卡牌本身和性相图标预期其倾向。若游戏在黑屏中退出，读档后继续尚未看完的过场，不会重复消耗物品。

### 5.6 合成与店主请求

- 合成不是“确认到晚上再结算”。点击合成后立即进入短计时流程，完成后当场消耗原料并生成产物。
- 店主请求也在玩家点击交付后当场消耗礼物、增加好感经验并显示店主反馈。
- 两者都不会使用每日愿望的黑屏过场。

## 6. 三日时间、商店与经济

### 6.1 白天收入

- 新游戏初始积蓄：20元。
- 每天白天收入：100元，包括第1天。
- 因此第1夜开始时有120元。
- 为未来新闻小游戏预留公式：`90元保底 + 0至30元表现奖励`。
- 当前 Demo 固定奖励10元，因此总收入固定100元。

### 6.2 营业排班

| 夜晚 | 营业零售店 | 设计目的 |
| --- | --- | --- |
| 第1夜 | 玩具店、花店、快餐店 | 低价入门、满足基本愿望、第一次接触气球先生 |
| 第2夜 | 玩具店、唱片店、书店 | 追忆与清醒选择、两种配方首次都可完成 |
| 第3夜 | 玩具店、花店、快餐店 | 安慰与助眠选择、提交气球先生的请求 |

回收站三个夜晚都开放，不计入三家零售店名额。

### 6.3 货位、补货与稀缺性

- 每家零售店开始时有6个独立货位。
- 新一天开始时，所有店铺（包括当晚不营业的店）只填补空货位，直到达到当前容量。
- 没有卖出的商品继续占据原位置，不会因换日自动刷新。
- 每个空位独立从该店已解锁的补货权重池抽取一个商品单位。
- 同款商品可以重复出现，但每一份都要单独选择、购买和占用一个位置。
- 当晚买空的货位保持空白，让玩家能直观看到稀缺性；不会实时补货。
- 解锁可以增加补货池，也可以直接增加店铺容量。
- 气球先生等级1是 Demo 中的扩容示例：玩具店从6格变为7格，并立即在新格放入一只发条飞蛾；以后每天也补到7格。

### 6.4 价格规则

- 商品按基础价格出售。
- 折扣后价格：`ceil(基础价格 × (1 - 折扣率))`，最低1元。
- 店主消费经验按实际支付金额计算。
- 普通购买物在回收站售价为 `floor(基础价格 × 0.8)`。
- 合成物使用固定回收价，始终低于最低原料成本，不能刷钱。
- 无退款；选入购物篮但尚未结账不构成购买。

## 8. 六个每日愿望

每天从大池子中抽取两个不同愿望。每个愿望只有一个槽位，可以独立确认和取消确认；两张卡只在下一天黑屏结算时一起消耗。

| ID | 标题 / English | 必要 | 可以 | 不可以 | 数值要求 |
| --- | --- | --- | --- | --- | --- |
| `wish_hungry` | 饿了 / Something to Eat | 食物 | 空 | 酒 | 食物≥2 |
| `wish_bedside` | 床头留一点东西 / Something by the Bed | 植物 | 灯、烛、枕 | 空 | 三种性相任一≥3 |
| `wish_stay_awake` | 今晚还不想睡 / Not Ready to Sleep | 空 | 灯、镜、烛 | 助眠 | 三种性相任一≥3 |
| `wish_remember` | 想起一点旧事 / Remember Something | 空 | 追忆、音乐、玩具 | 食物 | 三种直觉属性任一≥3 |
| `wish_settle_down` | 需要安静下来 / Settle Down | 空 | 放松、助眠 | 提神 | 两种属性任一≥3 |
| `wish_rain_close` | 雨声太近 / The Rain Is Too Close | 空 | 柔软、温暖、甜 | 易碎 | 三种属性任一≥3 |

### 8.1 抽取与防死档算法

愿望不是先随机完再期待玩家解决，而是由可满足性求解器选取：

1. 在当天可用愿望池中产生候选二元组。
2. 构造物品实例全集：当前未占用手牌 + 当晚营业商店每一个有货的独立货位。
3. 为两个愿望寻找两个不同实例，不能重复使用同一件物品。
4. 购买选择需要引用不同 `shelf_slot_id`，并同时满足实际货位和玩家当晚现有金钱。
5. 求解器计算最低购买成本；只有存在可行解的候选二元组才能进入随机池。
6. 从可行二元组中按存档 RNG 随机选择，并立刻把愿望 ID 写入存档。
7. 如果内容配置错误导致随机池为空，使用经过单元测试的当日保底组合；保底仍失败则停止推进并报告开发错误，绝不生成无法完成的存档。

求解时可以使用玩家已经持有的合成物，但不会假设玩家“未来可以合成某物”。每日愿望永远能只靠已有物与直接购物完成。

为了避免玩家在愿望生成后主动制造死档，所有不可逆操作还要经过“今晚仍可完成”模拟：

- 结账前使用付款后的金钱、买到的卡牌和剩余货位重新求解。
- 合成前使用消耗原料后的手牌、合成产物和剩余货位重新求解。
- 送礼或回收前使用移除该卡后的状态重新求解。
- 已确认愿望中的卡牌视为保留，不参与其他用途。
- 若操作会移除最后一条可行路径，则拒绝该操作并显示一句短反馈，例如“今晚还需要留一点给自己”。
- 两个愿望都确认后不再限制其他消费，因为每日结算所需卡牌已经保留。

默认 QA 种子选中：

- 第1夜：`wish_hungry` + `wish_bedside`
- 第2夜：`wish_stay_awake` + `wish_remember`
- 第3夜：`wish_settle_down` + `wish_rain_close`

## 9. 主角性相计数

主角保存四个整数计数器：灯、镜、烛、枕。

点击下一天并开始黑屏结算时，不把物品的性相数值直接加给主角，而是记录“出现过哪些性相”：

- 被消耗物品的某性相数值大于0，则对应主角计数 `+1`。
- 一件物品同时包含灯与烛，就分别增加灯1、烛1。
- 数值1与数值8对主角计数的贡献相同。
- 两件带灯的物品被用于两个每日愿望，结果是灯 `+2`。

点击“确认”不会改变这些计数；取消确认也没有任何数值副作用。只有下一天结算快照成功创建并消耗卡牌时，性相变化才生效。

界面只以短暂图标暗示此次变化，不展示复杂公式。

额外的剧情与首次合成可以使用单独的、明确写在内容中的计数变化：

- 首次合成童年的泰迪熊：镜 `+1`。
- 首次合成婴儿安抚熊：枕 `+1`。
- 首次合成清夜收音机：灯 `+1`。
- 首次合成潮汐收音机：烛 `+1`。

同一产物重复合成不会重复获得这项首次奖励。

### 10.3 合成操作

- 槽位类型满足但数值不足时，卡牌可以留在槽中，按钮禁用并说明差值。
- 三个槽位都有卡且数值全部满足时，显示将要生成的确定产物和预览文案。
- 玩家点击“合成”后，三个输入槽和对应卡牌立即锁定，开始2.5秒合成计时。
- 计时期间显示克制的进度动画和预览文案，不进入黑屏，也不播放每日愿望结果文案。
- 计时结束时进行一次原子操作：销毁三张原料、生成产物卡、应用首次合成奖励并自动保存。
- 合成产物当场出现在底部手牌栏，并播放短暂卡牌生成动画。
- 玩家可以在计时期间关闭或移动任务窗口；合成在全局状态层继续，不能通过关闭窗口取消或复制材料。
- 若游戏在计时中退出，存档保存 `active_synthesis`；读档后继续剩余计时，再完成同一次原子产出。
- 配方可以重复使用；只有首次产物奖励不会重复。

## 11. 气球先生好感度验证线

### 11.1 通用关系数据

所有店主都使用同一套关系状态接口：

- 当前经验。
- 当前等级。
- 累计实际消费金额。
- 已经发放的消费经验。
- 每日是否已经交谈。
- 当前请求与已完成请求。
- 对话和选择标记。

三日 Demo 只为玩具店的气球先生配置完整内容。其他老板可以交谈并显示占位短句，但不会错误地进入气球先生的事件。

### 11.2 经验来源

| 来源 | 经验 |
| --- | ---: |
| 每个夜晚第一次日常交谈 | +2 |
| 在该店累计实际消费每满10元 | +1 |
| 完成正式请求 | +6 |
| 送出更符合偏好的请求物 | 额外+2 |

消费经验使用累计差值结算：

```text
新增经验 = floor(结账后累计消费 / 10) - floor(结账前累计消费 / 10)
```

因此拆单不会额外刷经验。退款不存在，回收物品不会扣除已经获得的关系经验。

### 11.3 等级阈值与解锁

| 等级 | 称呼 | 所需总经验 | 解锁 |
| --- | --- | ---: | --- |
| 0 | 陌生 | 0 | 旧绒布、玻璃弹珠；普通交谈 |
| 1 | 眼熟 | 3 | 玩具店扩为7个货位；新货位立即出现发条飞蛾；第二段日常对话 |
| 2 | 愿望浮现 | 7 | 泰迪熊配方；“不会漏气的拥抱”请求 |
| 3 | 朋友 | 14 | 玩具店永久9折；Demo 好感小结局 |

等级只升不降。一次行为跨过多个阈值时，按顺序播放解锁提示，但不弹出长说明窗口。

### 11.4 三夜内容

第1夜交谈：

> 气球先生用手套按住自己的笑脸。松开以后，它仍然停在原来的弧度。
>
> “今天没有漏气。”他说，“这通常算是好消息。”

达到等级1：

> 他从柜台下面放出一只发条飞蛾。它沿着玻璃飞不起来，只好认真地走路。

此时玩具店新增第7个独立货位并放入发条飞蛾，不替换原有6个位置。从下一天开始，玩具店会补货到7个位置，发条飞蛾进入其补货池。

第2夜交谈：

> “气球适合被看见，不太适合拥抱。”
>
> 他想了想，又补充：“有没有一种不会漏气的拥抱？”

达到等级2后，解锁泰迪熊配方和请求 `request_balloon_hug`。

请求槽位：

```text
必要：teddy
可以：mirror / pillow
不可以：lamp / candle
提交：soft >= 4
```

两种泰迪熊都能完成请求：

- 童年的泰迪熊：基础请求经验+6；记录分支 `balloon_hug=memory`。
- 婴儿安抚熊：基础+6、偏好额外+2；记录分支 `balloon_hug=comfort`。

童年的泰迪熊结果：

> 他把熊举到和自己一样高。熊脸上的旧磨损让他的笑容第一次显得不那么孤单。

婴儿安抚熊结果：

> 熊陷进气球服柔软的腹部，没有发出任何漏气声。他很久没有把它拿开。

达到等级3：

> “以后便宜一点吧。”气球先生说，“不是促销。只是朋友不应该每次都看价签。”

## 12. 三日 Demo 的结束

第3夜确认两个每日愿望并点击下一天后：

- 先正常进入黑屏过场，消耗两件物品并显示第3夜的两段选择文案。
- 过场结束后原本应进入“第4天”，但实验版改为显示 Demo 结束页，不生成第4天内容。
- 如果完成气球先生请求，结束页附带对应分支的一句回声。
- 如果未完成请求，只显示中性的“商场仍有几盏灯没有熄灭”。
- 结束页提供“继续查看存档状态”和“返回标题”，不伪装成20天正式结局。

- 第20天普通结局。
- 提前解锁特殊结局。
- 主角四性相计数条件。
- 店主事件组合条件。
- 酒精灯小姐与灯泡男的非好感剧情标记。

- 画面完全变黑并应用每日物品消耗。
- 黑屏过场完成并生成新一天。
- 合成开始与合成完成。
- 店主请求提交。

写入采用临时文件再替换正式文件，避免中途退出损坏存档。随机种子、实际货位、已经抽出的愿望、确认状态和进行中的合成都必须保存，读档不能重新抽取或重复结算。

## 14. 数据资源与代码边界

内容使用 Godot `Resource` 与文本 `.tres` 文件保存，不把全部商品和剧情继续堆在一个巨大的 GDScript 数组中。

建议资源类型：

- `ItemDefinition`：价格、补货权重、解锁条件、属性、文本键、卡面资源。
- `ItemInstanceState`：玩家持有的具体卡牌。
- `ShelfSlotState`：店铺、货位 ID、当前位置和其中的单个商品单位。
- `SlotRule`：必要、可以、不可以、数值要求。
- `WishDefinition`：每日愿望、槽位、结果文案映射。
- `RecipeDefinition`：槽位、分支比较、产物和预览。
- `OwnerDefinition`：等级阈值、解锁和请求。
- `OwnerRelationState`：运行时经验与标记。
- `DailyWishSolver`：联合实际货位、金钱和物品实例的可满足性搜索。
- `SaveRepository`：存档序列化、版本检查和原子写入。

规则层不依赖具体 UI 节点，必须能在无渲染 GUT 测试中完成：

- 槽位类型判定。
- 数值门槛判定。
- 每日愿望确认、取消和黑屏结算状态机。
- 基于独立货位的每日愿望联合可满足性。
- 结账原子性。
- 合成计时、分支与原子消耗。
- 关系经验阈值。
- 存档往返一致性。

## 15. 分阶段开发计划

### 阶段A：新领域模型

- 新建物品实例、属性集、槽位规则、愿望和配方资源。
- 写入12件商品、6个愿望、2个配方。
- 实现纯规则测试。
- 不接 UI。

验收：数据能加载；所有槽位示例与配方分支测试通过；旧 Polyomino 规则不再被新领域调用。

### 阶段B：商店与底部手牌

- 重写购物交易，不再要求商品先进入任务。
- 每店建立6个独立货位、重复商品和逐格补货。
- 商品货架不可拖，购物篮引用具体货位并支持原子结账。
- 实现全局横向手牌栏和卡牌拖动。
- 改造回收站接收手牌。

验收：买到的卡才可拖；同款的两个位置能被分别购买；空货位只在下一天补充；离店购物篮处理正确；手牌在地图和商店之间保持。

### 阶段C：唯一任务窗口与槽位

- 重写右下角头像入口。
- 实现今日清单、配方、请求分页。
- 实现必要/可以/不可以放入判定、数值反馈和点击槽位高亮。
- 彻底移除空袋子与多 popup 状态。

验收：物品可在手牌和槽位之间直觉地来回拖动；任何时候只有一个任务窗口。

### 阶段D：三日循环与防死档

- 实现每日100元、三日排班和货位补充。
- 实现联合可满足性求解器与默认 QA 种子。
- 在结账、合成、送礼和回收前接入“今晚仍可完成”保护。
- 接入六个愿望、确认/取消、下一天黑屏过场、结果文案和主角性相计数。

验收：大量随机种子和购买序列模拟均不会生成死档；破坏最后可行解的不可逆操作会被拦截；两个愿望未确认时不能进入下一天；确认后可以取消换物；确认不会提前消耗或显示文案；黑屏结算只执行一次。

### 阶段E：配方

- 实现配方预览、2.5秒计时、分支优先、原子消耗和产物卡。
- 实现首次合成性相奖励和固定回收价。

验收：两条配方的两种产物均可实际获得；合成反馈在任务窗口中当场完成且不进入黑屏；中途关窗或读档不会复制材料；无法通过买卖合成物获利。

### 阶段F：气球先生关系线

- 实现通用好感状态、每日交谈和消费经验。
- 接入等级解锁、泰迪熊请求、分支结果与折扣。

验收：三夜内可以但不强制完成关系线；拆单不能刷经验；两种泰迪熊均有不同结果。

### 阶段G：新存档、清理与完整 QA

- 实现新存档和自动保存。
- 删除旧 Polyomino 运行时代码、场景、资源和测试。
- 检查中英两种语言、布局、运行日志和三日完整流程。

验收：读档不会重新抽愿望、货位或丢失槽位；黑屏和合成中断后均可准确恢复；仓库不存在新旧玩法双轨技术债务；完整检查全部通过。

## 16. 验收时需要重点判断的体验问题

规则与数值通过自动测试后，仍需要人工判断：

1. 底部手牌是否像“拥有的东西”，而不是开发工具栏。
2. 点击槽位后的高亮是否无需阅读说明就能理解。
3. 低数值卡可以放入但不能确认或执行，是否会造成有趣的试探而不是挫败。
4. 三日收入是否让玩家有选择，又不会因为害怕花钱而拒绝合成。
5. 四性相的选择是否被短文案自然表达，而不是显示成性格测验题。
6. 任务窗口与货架共存时，跨区域操作是否顺手。
7. 每日愿望、配方和店主请求是否看起来属于同一个世界，而不是三套菜单。
