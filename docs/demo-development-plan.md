# 《千禧年购物指南》玩法 Demo 开发计划

状态：主角界面、空袋子与回收站阶段（2026-07-24 更新）

## 1. 本阶段目标

把商场、商店和 Polyomino 拖放原型收束成一套可持续扩展的 Demo 循环：

1. 右下角购物袋是地图与商店共用的主角界面入口。
2. 每日目标、空袋子和已解锁剧情任务以可拖动 popup 管理。
3. 商品必须先拖进任一可容纳的格阵，再统一结账。
4. 每日目标提交后才允许进入下一夜；过夜时消耗其中物品。
5. 剧情任务由店主交谈解锁，解锁后才出售对应特殊物品。
6. 回收站按原价 80% 回收普通已购物品，为误购提供经济出口。

本阶段暂不做最终数值平衡和正式美术；玩家界面保持夜晚梦核商场方向，并完整支持 `zh_CN` / `en` 即时切换。

## 2. 已锁定规则

### 2.1 主角界面

- 地图和商店右下角常驻放大的 `bag.png`，贴紧屏幕底部，悬停切换为 `bag-light.png`；它始终绘制在自己打开的 popup 下方。
- 点击购物袋打开可拖动的近黑色主角界面，任务入口是略微倾斜、缓慢漂浮的卡片。
- “每日目标”和“空袋子”始终存在；泰迪熊、金鱼、磁带按世界阶段解锁后出现。
- 卡片只打开任务，不接受骨牌投放。
- 主角界面和各任务格阵都是独立、可拖动、可同时打开的 popup。
- 每个非空袋子格阵左下角有一个小图标，用于打开或关闭共享空袋子；打开时优先贴在当前格阵左侧，空间不足才回到固定位置。
- 关闭任何 popup 都不受其中物品影响；关闭只隐藏空间，不改变物品状态。
- 已提交的每日目标和已完成剧情任务使用暖金色完成态；剧情任务保留为记忆卡片，点击可回看结果短文案。

### 2.2 空袋子与物品归属

- 空袋子是一个共享的 8×8 无遮罩格阵，普通物品、特殊物品和待购物品都可放入。
- 不再存在每任务整理区、无限数量背包列表或“整理区必须为空”的门禁。
- 每个物品实例有唯一 ID、所有权、所在空间、网格坐标与旋转状态。
- 已购物品可在同时打开的格阵间直接拖动；合法落下后立即改变归属。
- 非法放置必须回到原位，不得复制、遗失或改变所有权。
- 特殊物品在正式任务中只能进入对应剧情任务，但可进入空袋子中转。

### 2.3 购物与结账

- 商店保持左侧商品、右侧老板的布局；商品卡不提供购买 `+` 按钮。
- 从商品架拖动时创建待购实例；待购实例必须合法放入每日目标、对应剧情任务或空袋子。
- 任务不必填满即可结账。结账统一复核营业状态、库存、资金与待购实例位置，再原子扣款、扣库存并改为已拥有。
- 待购物品可拖回商品区取消；离店时若仍有未付款实例，先询问“回去结账／离开”，确认离开后才将它们放回货架。
- 真正离开商店或成功进入下一夜时，关闭主角界面及其打开的全部任务 popup，但不改变已拥有物品的归属。
- 失败交易不得部分扣款、扣库存或改变已有物品布局。

### 2.4 每日目标

- 使用 7 个手工设计、外接尺寸不超过 4×4、连通且无内部空洞的模板按星期循环。
- 只接受普通物品，不要求特殊物品，也没有属性门槛。
- 恰好填满时出现提交；提交前仍可调整，提交后布局锁定并记录最高属性文案。
- 单一最高属性产生灯、镜、花、雾文案；并列时使用混合意象文案。
- 地图和商店中的“下一夜”始终可点击；未提交每日目标时只显示短提示，不改变日期。
- 成功过夜时消耗每日目标物品、增加 100 元、刷新营业安排和库存，并创建新目标。

### 2.5 剧情任务

- 阶段 0：玩具店交谈解锁泰迪熊与缺耳泰迪熊商品。
- 泰迪熊提交后进入阶段 1；快餐店交谈解锁金鱼与鱼骨。
- 金鱼提交后进入阶段 2；唱片店交谈解锁磁带与磁带商品。
- 剧情任务必须恰好填满、包含对应特殊物品并满足属性规则。
- 对应店主交谈提交后消耗该任务全部物品；任务卡变暗并保留回看。
- 特殊商品终身限购一次，不能在回收站出售。

### 2.6 回收站

- 回收站是第六个地图入口，始终营业，不出售商品。
- 将已拥有的普通物品从任一格阵拖到左侧回收区域，即加入当前回收单；区域不固化或逐件显示骨牌，只显示件数与预计收入。
- 待购物品、特殊剧情物品和已提交／已完成任务中的锁定物品不能加入回收单。
- 单件回收价为 `floor(原价 × 0.8)`，结算时统一加钱并永久移除物品。
- 结算前可以取消回收，让全部物品原样回到来源格阵。
- 结算使用独立原子交易，失败不得丢失物品或改变余额。

## 3. UI 结构

```text
Main
├─ MallMap / ShopScreen / RecycleShop
├─ ProtagonistBagButton
└─ PopupLayer
   ├─ ProtagonistPanel
   │  └─ TaskEntryCard × N
   └─ TaskPuzzlePopup × N
      ├─ PuzzleBoard
      ├─ EmptyBagToggle（空袋子自身除外）
      ├─ 简短属性／结果文案
      └─ 提交动作（每日目标）
```

弹层状态由共享 `GameState` 持有。地图和商店只提供当前视觉上下文与拖放来源，切换场景不复制物品。

## 4. 状态模型

### 4.1 `PuzzlePieceState`

- `BOARD`：位于一个任务或空袋子格阵中。
- `RECYCLE_CART`：已暂存进本次回收单，结算前保留原始位置快照。
- `task_id` 对 `BOARD` 物品不能为空；拖动模板未合法落下前不进入共享实例表。
- 跨 popup 拖动复用同一个实例，只有合法落下才原子更新位置。

### 4.2 每日与剧情状态

- `DailyGoalState` 保存当前日模板、提交状态、提交属性统计和结果键。
- `talk_to_owner(store_id)` 按世界阶段解锁剧情任务。
- 特殊商品可见性由任务已解锁、任务未完成、商品未购买共同决定。
- 结账只确认购买，不负责解锁任务。

### 4.3 过夜门禁

`advance_day()` 在 mutation 前检查：

1. 每日目标已提交。
2. 不存在待购买实例。
3. 不存在未结算的回收单。

通过后只消耗每日目标物品，保留空袋子和未完成剧情任务布局，再增加工资、推进日期并刷新库存。

## 5. 清理约束

替代功能接通后直接删除，不保留兼容分支：

- 每任务整理区及其折叠 UI、门禁、提示、枚举和测试。
- 商店旧“商品／无限背包”标签、购买 `+` 按钮和点击购买路径。
- `PuzzlePieceState.Location.INVENTORY` 及“拖出格阵返回无限背包”逻辑。
- 正式游戏对旧 `InventoryPanel`、`PieceInstanceCard` 的依赖。
- 购买特殊商品后解锁任务的旧状态分支和旧翻译键。

`PuzzleLab` 继续作为开发者拖放验证场景存在，不复用正式 UI 的工具箱视觉。

## 6. Checkpoint

### CP-A：共享空袋子

- 删除整理区模型、UI、门禁、提示与测试。
- 接入 8×8 空袋子任务卡和所有任务 popup 的快捷开关。
- 允许购买物进入空袋子并正常结账；特殊物品仍受正式任务规则限制。
- 定向 GUT、完整检查和 Git checkpoint。

### CP-B：回收领域模型

- 实现回收单的加入、取消、80% 计价、结算和原子性。
- 接入 `GameState`，覆盖普通／特殊／待购／锁定物品边界测试。
- Git checkpoint。

### CP-C：回收站界面与地图

- 增加第六个地图入口、回收店场景和中英文本。
- 支持从任一已打开格阵拖到回收区域、取消和结算。
- 删除回收商品的实体陈列，仅保留短状态与预计收入。
- 运行时检查中文／英文、层级、日志和截图。

### CP-D：清理与交付

- 删除无引用脚本、信号、翻译键和过时测试辅助代码。
- 运行 `tools/check.ps1`、完整 GUT、`git diff --check`、`git diff` 和 `git status`。
- 使用 Godot MCP 检查运行树、截图、编辑器与游戏日志；停止测试游戏。
- 提交 checkpoint；大阶段经确认后推送 `main`。

## 7. 自动验收不变量

- 同一实例不能同时出现在两个格阵，跨任务拖放不会复制。
- 空袋子接受任意物品；特殊物品不能进入错误的正式任务。
- 待购物品位于合法格阵即可结账；失败交易不扣钱、不扣库存。
- 关闭 popup 不丢失、不移动物品，也不阻止结账。
- 每日目标未提交不能过夜；提示出现但按钮不锁定。
- 过夜只消耗每日目标，不改变空袋子和未完成剧情任务布局。
- 回收站只接受已拥有普通物品；按 80% 向下取整，结算后物品消失。
- 取消回收时所有物品精确回到原任务、位置和旋转。
- 中文与英文都无缺失翻译键或关键布局溢出。

## 8. 暂不处理

- 最终价格、库存、回收比率和每日目标难度平衡。
- 正式对话、音效、复杂动画、完整存档。
- 自动整理、自动解题、镜像翻转、手柄、触屏和正式无障碍适配。

本轮试玩重点：空袋子是否足够自然、任务间调度是否顺手、回收误购物品是否清晰，以及这些功能是否仍保持“游戏界面”而非工具箱感。
