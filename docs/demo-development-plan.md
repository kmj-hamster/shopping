# 《千禧年购物指南》玩法 Demo 开发计划

状态：主角界面与每日目标重构阶段（2026-07-24 定稿）

## 1. 本阶段目标

把现有可玩的商场、商店和 Polyomino 拖放原型收束成正式 Demo 循环：

1. 右下角购物袋是地图与商店共用的主角界面入口。
2. 主角界面以“购物袋之脑”为意象，管理每日目标和剧情任务。
3. 所有已购买物品必须位于一个未完成任务的正式格阵中，不再存在无限背包。
4. 商店商品必须先拖入任务格阵，才能结账购买。
5. 每天必须提交每日目标，才能进入下一天；过夜时消耗其中物品。
6. 剧情任务由店主交谈解锁，解锁后才出售对应特殊物品。

本阶段暂不处理最终数值平衡和正式美术，但玩家界面必须保持夜晚梦核商场的方向，并完整支持 `zh_CN` / `en` 即时切换。

## 2. 已锁定的玩家规则

### 2.1 主角界面

- 地图和所有营业商店右下角常驻 `bag.png`；悬停时切换为 `bag-light.png`。
- 点击购物袋打开可拖动的主角界面 popup。
- 主角界面使用近黑、低对比的袋内背景；任务入口表现为略微倾斜、缓慢漂浮的矩形卡片。
- 卡片只负责打开任务，不接受骨牌投放。
- “每日目标”始终存在；泰迪熊、金鱼、磁带任务按世界阶段解锁后出现。
- 已完成剧情任务保留为变暗的记忆卡片，点击后只回看结果短文案。
- 主角界面和每一个任务格阵都是独立、可拖动、可以同时打开的 popup。
- 地图中打开的任务 popup 默认居中；商店中默认出现在右侧，保留左侧商品与右侧店主的现有商店构图。

### 2.2 物品归属

- 每个物品实例有唯一 ID、所有权、所在任务、所在区域、网格坐标和旋转状态。
- 正式运行时只有两种空间区域：任务正式格阵与该任务的临时整理区。
- 不再存在无限背包、背包标签页或“购买后暂存背包”的路径。
- 已拥有物品可以在同时打开的任务 popup 之间直接拖动；合法落下后立刻改变任务归属。
- 非法跨任务放置必须原样回到来源，不得复制、遗失或改变所有权。
- 特殊物品只能放入自己对应的剧情任务，不能进入每日目标或其他剧情任务。

### 2.3 独立整理区

- 每个未完成任务拥有自己的临时整理区，位于正式格阵左侧。
- 整理区宽度固定为 4 格，高度与右侧正式格阵的外接高度相同。
- 整理区默认折叠；点击袋口式把手后展开，popup 随之横向变宽。
- 待购买和已拥有骨牌都可以临时放入整理区。
- 整理区非空时，禁止结账、提交、关闭对应 popup 和进入下一天。
- 受阻操作只给出短提示和轻微抖动，不使用说明段落。
- 整理区不是库存容器；它只能服务于当前布局重排，不能跨夜或隐藏保存。

采用独立整理区而不是全任务共享空袋的原因：共享空间会重新成为一个有限背包，并模糊物品属于哪个任务；独立整理区能保持归属清晰，多 popup 直接拖动已经足以完成跨任务转移。

### 2.4 购物与结账

- 商店保留“左侧商品、右侧老板”的现有主体布局。
- 删除商品右侧的购买 `+` 按钮和商店中的背包标签页。
- 从商品骨牌开始拖动时创建待购买实例；拖回来源或取消拖动时不产生购买。
- 待购买实例可以临时进入整理区，但只有位于一个合法正式任务格阵中时才能结账。
- 任务不必填满即可结账。
- 结账继续使用现有原子交易：统一复核商店、库存、资金和所有待购实例的位置，然后一次性扣款、扣库存并转为已拥有。
- 钱不足、库存不足、待购实例未进入正式格阵或任一整理区非空时，结账失败且不改变现有状态。
- 离开商店会取消该店全部待购实例，但已拥有物品的位置不变。
- 玩家不会购买“盈余物品”：正式格阵之外没有可持久存放的位置，格阵填满后也无法继续塞入商品。

### 2.5 每日目标

- 使用 7 个手工设计的连通模板按星期循环，不随机生成。
- 每个模板外接尺寸不超过 4×4，可以从矩形边缘扣除格子形成异形，但内部不能有空洞。
- 每日目标只接受普通物品，不要求特殊物品，也没有属性过关门槛。
- 格阵恰好填满且整理区为空时出现“提交”动作。
- 提交前可以随时移动物品；确认提交后布局锁定、不可撤销，并记录最高属性结果。
- 单一最高属性分别产生灯、镜、花、雾短文案；最高属性并列时使用混合意象文案。
- 提交后才解锁“下一天”。提交物品仍显示在格阵中，进入下一天时统一消耗。
- 新一天增加 100 元、刷新营业店铺与普通库存，并创建新每日目标。

### 2.6 剧情任务

- 阶段 0：在玩具店与店主交谈，解锁泰迪熊任务与缺耳泰迪熊商品。
- 完成泰迪熊并向玩具店店主提交后进入阶段 1。
- 阶段 1：在快餐店与店主交谈，解锁金鱼任务与鱼骨商品。
- 完成金鱼并提交后进入阶段 2。
- 阶段 2：在唱片店与店主交谈，解锁磁带任务与磁带商品。
- 剧情任务必须恰好填满、包含对应特殊物品并满足既有属性规则。
- 剧情任务仍由对应店主交谈提交；提交后格阵中全部物品消耗，任务卡变暗并保留结果回看。
- 特殊商品终身限购一次。当前横向 1×7 鱼骨改为外接矩形不超过 4×4 的鱼骨异形。

## 3. UI 结构

```text
Main
├─ MallMap 或 ShopScreen
├─ ProtagonistBagButton（常驻右下角）
└─ PopupLayer
   ├─ ProtagonistPanel（可拖动）
   │  └─ TaskEntryCard × N
   └─ TaskPuzzlePopup × N（可拖动、可同时打开）
      ├─ OrganizerBoard（4×任务高度，可折叠）
      ├─ PuzzleBoard（任务遮罩）
      ├─ 简短属性状态／结果文案
      └─ 提交动作（按任务类型决定位置与可用性）
```

弹层由 `Main` 统一持有，以保证从地图进入商店或返回地图时任务状态不复制。地图与商店只提供当前视觉上下文和商品拖放来源。

## 4. 状态模型

### 4.1 `PuzzlePieceState`

- 删除 `INVENTORY` 语义。
- 区域使用 `TASK_BOARD` / `ORGANIZER`。
- `task_id` 在正式运行时不能为空；待购模板尚未成功落下前不是全局状态中的物品实例。
- 所有跨 popup 拖动都复用同一份实例，成功落下才原子更新位置。

### 4.2 `DailyGoalState`

保存：

- 当前日与模板 ID。
- 是否已提交。
- 提交时的属性统计与主导结果键。
- 当前正式格阵和整理区中的物品由统一实例表按 `task_id` 查询，不保存第二份副本。

### 4.3 解锁与特殊商品

- `talk_to_owner(store_id)` 负责按世界阶段解锁剧情任务。
- 特殊商品可见性由“对应任务已解锁、任务未完成、商品未购买”共同决定。
- 结账不再负责解锁任务，只负责确认特殊商品已购买。

### 4.4 过夜门禁

`advance_day()` 在任何 mutation 前依次检查：

1. 每日目标已提交。
2. 所有整理区为空。
3. 不存在待购买实例；商店内请求过夜时先沿用现有取消购物车确认。

检查通过后消耗每日目标物品、增加工资、推进日期并刷新库存。任何检查失败都不得部分改变状态。

## 5. 清理范围

以下旧结构在替代功能接通后直接删除，不保留兼容分支：

- 商店的“商品／无限背包”标签及其渲染路径。
- 商品卡的购买 `+` 按钮和 `add_requested` 点击购买路径。
- `PuzzlePieceState.Location.INVENTORY`。
- `PuzzleBoard.return_removed_to_inventory` 及“拖出格阵返回背包”逻辑。
- 正式游戏对 `InventoryPanel`、`PieceInstanceCard` 的依赖；若无开发测试引用则删除文件。
- 商店内嵌的单任务板、任务 Tab 和重复属性面板。
- “购买特殊商品后解锁任务”的状态分支与相关旧翻译键。
- 与旧背包／旧解锁规则绑定的测试，改写为新不变量测试，不保留双重行为。

`PuzzleLab` 继续作为开发者拖放验证场景存在，但不得复用正式主角界面的视觉或库存语义。

## 6. 开发 Checkpoint

### CP-A：领域模型与计划基线

- 更新任务、物品位置、每日目标和解锁状态。
- 加入 7 个每日模板与新版鱼骨形状。
- 为过夜门禁、提交消耗、特殊物品限制、跨任务归属和交易位置约束增加 GUT 测试。
- 通过受影响的定向 GUT 测试后提交 Git checkpoint。

### CP-B：主角界面

- 加入购物袋 hover 入口。
- 实现可拖动主角 popup、漂浮卡片、完成卡片状态。
- 支持从地图和商店打开多个可拖动任务 popup。
- 同时检查中文与英文布局后提交 checkpoint。

### CP-C：格阵、整理区与购物

- 把正式 `PuzzleBoard` 移入任务 popup。
- 实现独立可折叠整理区、跨 popup 拖放及关闭门禁。
- 商品卡改为直接拖动；接通待购位置校验、结账与取消。
- 删除商店旧背包、加号和内嵌任务 UI。
- 完成 GUT 与运行时交互检查后提交 checkpoint。

### CP-D：每日目标与剧情循环

- 接通每日提交、文案、锁定、过夜门禁和次日消耗。
- 把剧情解锁从结账迁移到店主交谈。
- 保持三任务顺序、店主提交和完成总结。
- 完整跑通至少两个夜晚与第一剧情任务后提交 checkpoint。

### CP-E：清理与交付

- 删除无引用旧脚本、旧信号、旧翻译键和过时测试辅助代码。
- 运行 `tools/check.ps1`、完整 GUT、`git diff --check`。
- 通过 Godot MCP 检查运行树、中文／英文截图、编辑器日志与游戏日志。
- 停止测试游戏，提交并在大 checkpoint 推送 `main`。

## 7. 自动验收不变量

- 没有任何已拥有或待购实例处于无任务归属状态。
- 同一实例不能同时出现在两个格阵，跨任务拖放不会复制。
- 特殊物品只能进入自己的剧情任务。
- 整理区非空时不能结账、提交、关闭对应 popup 或过夜。
- 待购物品未在正式格阵时不能结账；失败交易不扣钱、不扣库存。
- 每日目标未提交不能过夜；提交后过夜只消耗该日目标物品。
- 进入新一天只刷新库存和每日目标，不改变未完成剧情任务布局。
- 店主交谈只解锁当前阶段任务一次；购买特殊商品不会反向解锁任务。
- 中文与英文都不出现缺失翻译键或关键布局溢出。

## 8. 本阶段暂不处理

- 最终价格、库存和每日目标难度平衡。
- 正式对话内容、音效、复杂动画和完整存档。
- 自动整理、自动解题、镜像翻转、退款和出售。
- 手柄、触屏和正式无障碍适配。

本阶段完成后，下一轮试玩重点是：多 popup 是否易于管理、独立整理区是否真的有帮助、每日目标是否形成自然的过夜节奏，以及直接拖商品进任务的购买过程是否仍然顺手。
