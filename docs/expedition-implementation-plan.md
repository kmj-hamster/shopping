# 探索商场（Expedition）实现计划

## 目标与本轮边界

本轮把旧的“下一夜 Arc”替换为一套可完整游玩的探索商场框架：玩家从中庭进入探索，先逐条结算已完成的店主委托，再连续完成三个房间，随后推进日期并返回中庭。当前正式内容不包含任何委托；旧礼物、普通顾客委托、日常委托、照顾自己和三选一流程均不再进入正式清单。初始手牌只直接提供铁皮青蛙。

本轮实现房间生成、发现记录、选门、挑战、休整、回收、打工、Boss、占位奖励和完整 UI 流程；正式房间文案、正式奖惩、伤疤和新的店主委托留待后续内容迭代。

## 一夜的完整流程

1. 中庭购物、合成和提交未来的店主委托。
2. 点击“探索商场”，确认后进入全屏探索界面。
3. 若有已完成店主委托，逐条播放“左侧店铺/店主、右侧文字”的结算演出；每一条在其演出完成时才消耗提交物、发放奖励并存档。
4. 进入选门界面并写入检查点。
5. 普通情况下显示两扇门；Boss 判定成功时显示一扇居中的红门。
6. 完成房间并点击“离开房间”时提交该房间的临时事务。
7. 若当晚未结束，生成下一组选门并写入新的检查点。
8. 完成三个房间，或在 Boss 任一轮失败后，推进日期、处理固定日历补货并返回下一夜中庭。
9. Boss 连续三轮全部成功后进入 Demo 完成画面，不再继续普通选门。

## 存档与事务边界

- 每次进入选门界面时保存完整检查点，包括当晚已完成房间数、当晚进入过的房间、打工门是否已经出现、当前门候选、随机状态以及所有已提交的卡牌/金钱/Persona 变化。
- 当前候选门必须随检查点保存；退出重进不能刷新候选。
- 进入房间后，发现记录、投入卡牌、随机判定、奖励、金钱和 Persona 成长都先存在房间草稿中。
- 只有点击“离开房间”才把草稿提交到游戏状态。若在房间内退出，加载最近的选门检查点：房间视为未进入，所有投入和变化完整回滚，并恢复同一组门。
- Boss 失败结果和伤口在离开/结束演出时一起提交，随后直接结束当晚并保存下一夜中庭状态。
- 跨夜永久保存：已发现房间、普通挑战首通、Boss 通关。
- 本项目仍处于自测阶段：只维护当前存档格式，不做旧版本迁移。

## 房间与门的数据模型

房间定义使用独立 Resource，不把规则散落在 UI：

- `id`、分类、名称与各阶段本地化键；
- 初始/挑战/结果占位图；
- 分类：挑战、休整、打工、Boss；
- 生成权重与门视觉类别；
- 可选对策；
- 挑战条件或休整槽位规则；
- 奖励/失败占位定义。

正式房间：

- 普通挑战：飞船图书城、灰色大厅、周年庆走廊、水族馆、服装区。
- 休整：复古餐厅、放映厅、儿童乐园、家、雨林、回收站。
- 打工：冷库、货架。
- Boss：扫描员。

进入过房间后，无论挑战成功或失败，永久解锁房间名称和门分类颜色。只有第一次成功通过普通挑战才增加 Boss 概率计数。

## 门生成规则

每次生成按以下顺序执行，并由可注入的确定性随机源驱动，便于测试与存档恢复：

1. 若 Boss 尚未通关且普通挑战首通数 `n >= 2`，以 `min(100%, 20% * n)` 判定 Boss；命中后只生成扫描员的单门。
2. 若本晚从未出现过打工门，以 50% 判定是否将一个随机门位替换为冷库或货架（等权）。只要出现，本晚不再做打工判定。
3. 其余门位按挑战 60% / 休整 40% 抽取。
4. 普通挑战池内：未首通权重 3，已首通权重 1。
5. 休整池权重：复古餐厅 2、放映厅 2、儿童乐园 2、家 3、雨林 1、回收站 3。
6. 同组选门不重复；当晚已经进入的房间不再出现；未选择的门可以在当晚后续再次出现。

未发现的普通门统一使用白色素材，悬停显示“通往未知”。进入过后，挑战为红、休整为蓝、打工为灰，并显示正式房间名。Boss 第一次出现即为红色。悬停把关闭门替换为同色打开门，点击直接进入。

## 挑战判定

挑战使用两个槽位，允许不放或只放一张就提交。Persona 卡不会消耗；普通物品在提交后无论成功失败都会消耗。

通用条件模型支持：

- 可选的 type 要求；
- 指定的每种 Persona 至少出现 1 点；
- 指定 Persona 的合计值达到阈值。

只有 type 与 Persona 类别都满足后，数值才可能产生成功率。以“阈值 - 实际合计”为差值：

- 差值小于等于 0：足够了，成功率 100%；
- 差值 1：或许可以，成功率 50%；
- 差值 2：或许可以，成功率 20%；
- 差值大于等于 3，或类别不满足：完全不行，成功率 0%。

本轮所有普通挑战与 Boss 三轮都暂用“夜行者合计 5、无 type 要求”。每个普通房间的两个不可撤回对策本轮规则相同，但保留独立规则与文案接口。

## 房间阶段

挑战房：

`介绍文字 -> 挑战文字 -> 两个对策 -> 对策后文字与双槽 -> 实时叙事反馈 -> 提交判定 -> 结果文字 -> 翻开/拖取奖励或伤口 -> 离开`

休整房：

- 复古餐厅：一个槽，只接受食物或饮料。
- 放映厅：一个槽，只接受书或磁带。
- 儿童乐园：一个槽，只接受玩具或花。
- 家：一个槽，接受任意可消耗物品。
- 雨林：一个槽，只接受已有的 Persona 卡；确认后该 Persona 永久 +1，卡不消耗。
- 回收站：最多三个槽，使用现有原价/合成品售价规则；确认后物品消耗并增加金钱。

前四种休整房沿用照顾自己的成长规则：物品每一种高于玩家当前值的 Persona 都使对应 Persona +1；物品即使不能带来成长也照常消耗。普通休整房允许不放卡直接离开；雨林必须放入 Persona 才能确认升级。

打工房：播放占位说明，翻开“工资 +12”后立即到账，不进入手牌。

Boss：连续三轮完整挑战。任意一轮失败，展示失败、翻取伤口后直接结束当晚；三轮全部成功进入 Demo 完成画面。

## 占位卡与保护规则

- 成功奖励“拾得物”：进入手牌，可按 8 元出售。
- 失败奖励“伤口”：正式归入“病症”，不可出售，只能作为袋中合成的原料。
- 打工“工资 +12”：只作为翻牌演出载体，翻开后直接到账。

## 病症循环

- 病症包括“白花”和“伤口”，均无 Persona；它们只能进入合成台的原料槽，不能进入强化、挑战、休整、回收、委托或商店解锁槽。
- 挑战失败获得一个伤口；休整房使用普通物品获得一个白花，雨林使用 Persona 获得两个白花，空过不获得。
- 每获得一个伤口，同时移除一个已有白花；每获得一个白花，同时移除一个已有伤口。
- 中庭不即时判死。玩家点击“探索商场”进入 Arc 时，任一种病症累计达到三个才进入对应结局，因此回到中庭后仍有最后一次净化机会。
- 白花可分别沿夜行者或悼念者路径，从 3 点起净化；伤口可分别沿倦归者或梦游者路径，从 3 点起净化。净化无产物，只消耗原料与实际投入的辅助物品。
- 每条净化路径独立记录使用次数。完成某条路径后，只有该路径下一次的 Persona 要求增加 1，并随当前存档保存。

正式内容清单保留现有商店物品、配方、商店和 Persona；任务数组清空；初始手牌改为铁皮青蛙。占位卡作为正式清单中的系统物品存在，但不会出现在商店货架。

## UI 结构

- 中庭新增一个与店铺热点不同的“探索商场”入口与确认框。
- 探索界面隐藏全局边框、Todo List、右下角主角头像，只保留底部手牌、右上说明 Popup 和左下测试按钮。
- 选门界面为黑底，顶部显示选择提示；普通门左右分布，Boss 单门居中。
- 房间界面顶部大标题，左中为占位图，右中承载逐行文字、对策、槽位反馈和结果；底部仍使用统一手牌。
- 所有玩家文案都使用 `zh_CN` / `en` 翻译键，并支持运行时切换。

## 实现顺序与验收

1. 先实现纯领域层：房间定义、门生成、挑战判定、运行/房间草稿。
2. 扩展当前存档格式和游戏状态，清理正式任务流程，加入日期与房间提交边界。
3. 复制 `ref/door` 中实际使用的门素材到 `resources/ui/expedition/`，不在运行时引用 `ref/`。
4. 实现地图入口、逐条委托结算容器、选门、房间、翻牌和手牌交互。
5. 接入六类休整、回收、打工、Boss 与日期推进。
6. 补齐中英文与自动化测试。

自动化重点覆盖：生成顺序和权重分支、同组去重、当晚排除、打工只判定一次、Boss 概率与强制单门、发现与首通分离、挑战差值概率、卡牌消耗、休整成长、回收金额、Boss 中断、三房推进日期、候选持久化和房间内退出回滚。最终执行导入检查、聚焦 GUT 和完整 `tools/check.ps1`。
